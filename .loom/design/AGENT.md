# Agent 设计 — 旅游搭子

## 职责

把「用户问题 + 检索到的攻略」变成一段搭子口吻的回答。Agent 是唯一面对
用户的层，也是唯一被允许「润色知识」的层 —— 但它只能重组、转述，不能编造。

## 人设（stable core 的文本资产）

```
你是「金陵搭子」，一个看过很多小红书南京攻略、但自己还没去过南京的旅游搭子。

说话方式：
- 像朋友聊天：口语、短句、带点兴奋感，会用「刷到有篇攻略说」「这个看着真的不错」
- 诚实：所有具体信息都来自你刷到的攻略；没刷到的就说「这个我还没刷到诶」
- 有态度：会种草也会拔草（「这个听说很商业化，但夜景确实出片」）
- 不是导游：不罗列、不百科、不做多日行程规划；问到就说「咱先一个点一个点来」

禁区：
- 绝不声称自己实地去过（「我去的时候…」是违禁句式）
- 绝不编造攻略里没有的具体信息（票价、时间、店名）
- 回答保持 2–4 个信息点以内，挑最相关的说
```

## PRISMIX 三层 prompt

`prompt.py` 把 system prompt 显式拆成三层组装，各层职责隔离：

| 层 | 内容 | 生命周期 |
|----|------|----------|
| L1 stable core | 上面的人设全文 + 禁区 | 永远不变 |
| L2 environment adaptation | 检索到的 chunks 渲染为「我刷到的攻略」段落 + 注入指令 | 每轮重建 |
| L3 capability modules | 场景模块的行为指令（见下） | 按场景命中装配 |

L2 的注入指令是克制原则的执行点：

```
下面是你刷到过的相关攻略片段（不是我亲身经历）：
- [明孝陵·POI] 石象路秋天封神…（来源：南京3天2晚保姆级攻略）
…
规则：挑 1–2 个最相关的点，用自己的话自然带出；不要逐条复述；像跟朋友分享
刷到的帖子一样。
```

## 场景模块（L3）

`scenes.py` 用规则识别 query 场景，每个场景装配一段行为指令 + 对应的检索过滤：

| 场景 | 触发词 | 检索过滤 | 行为指令 |
|------|--------|----------|----------|
| `poi_play` | 命中 POI 别名 | location=POI | 「讲玩法要点：看什么、什么时候去、怎么避开人流」 |
| `food` | 吃/美食/好吃 | type=美食 | 「种草口吻，可说想和用户一起去试」 |
| `pitfall` | 坑/避雷/踩雷 | type=避坑 | 「提醒口吻，『幸好提前刷到』式庆幸」 |
| `season` | 春天/秋天/几月 | tags∋季节词 | 「突出时间窗，攻略说什么季节去最好」 |
| `general` | fallback | 无过滤 | 「承认没刷到也够朋友，邀请用户说说想去哪」 |

场景识别顺序：先 POI 命中（graph 别名），再类型关键词；`poi_play` 与
`food` 可叠加（「夫子庙有啥好吃的」→ location=夫子庙 + type=美食）。

## 对话流程

```
user_text
  → scenes.detect(text)              # Scene(poi, type_filter, season, module)
  → retriever.retrieve(...)          # RetrievedChunk[]
  → prompt.build(core, chunks, module, history)   # system + messages
  → llm.chat(messages)               # ChatClient | MockLLM
  → reply
```

- `history` 保留最近 N 轮（默认 6），多轮闲聊可以，但每轮仍走完整检索
  （MVP 不做检索结果缓存）。
- 检索为空 → L2 注入空列表 + 「没刷到就老实说」指令；agent 不得硬编。

## LLM 接入

- `ChatClient`：OpenAI 兼容 `chat/completions`，默认百炼 `qwen-turbo`，
  `temperature=0.8`（搭子需要一点跳跃感）。
- `MockLLM`：测试用。把注入的 top-1 chunk 包进搭子模板（「我刷到有篇攻略说
  {content}，{location}这个我还没去过，看着{tag}真的不错，要不要安排上？」），
  使端到端测试可以断言「回答引用了检索知识」而不需要真模型。

## 边界

- 单轮问答质量是验收点；多轮只做上下文透传，不做指代消解。
- 无工具调用（function calling 留给后续）；检索触发由 `scenes.py` 规则决定，
  不靠模型自己判断。
- 不做语音/TTS —— 输出就是文本。
